# AI 戏精导演 V1.1 · 八位全身角色

1.3 版本默认按剧本提示拍摄。先选择具体短片和人数，再按演员昵称、动作提示和倒数逐幕完成。六幕拍完自动生成 MP4，等待和提示时间不会进入成片。完整流程见《短片版使用说明.md》。


本版本新增破冰短片功能。双击 start.cmd 后，在页面下方的短片工作台录制并生成 MP4。首次启动会自动准备视频工具，完整使用方法见《短片版使用说明.md》。

新增三个 AssetFurnace 模型的原始文件没有骨骼或动画。`imported-avatar.mjs` 按各角色站姿建立 20 个身体关节，生成平滑蒙皮权重，并接入现有 `AvatarDriver`。背包和背部装备降低手臂权重，游侠网格中连接手臂与背部装备的三角面在运行时分开处理，减少拉扯。`jaw-morph.mjs` 为新增三款生成嘴唇分离、下颌形变和口腔内部网格，直接跟随摄像头的 `jawOpen` 分数。新增角色目前暂无眨眼表情。使用的是近似身体蒙皮和程序生成的张嘴形变，衣物和大幅关节弯曲仍可能出现局部变形。原始 GLB、`LICENSE.txt` 和 `provenance.json` 一并保留在各角色目录。

八位人物均接入前端九个动作，包括扶额、双手抱头、转头、单手举高、双手举高、挥手、展开双臂、歪头和张嘴。摄像头模式使用实际关键点驱动，扶额与抱头按角色头身比例校正手部接触位置。`action-poses.mjs` 的合成动作只用于预览、台词示例和测试。3D 预览可逐项选择九个动作，另保留下蹲和抬腿预览。

在主页选择人物卡片，或打开“查看 3D 角色”，选择对应人物和动作即可预览。`tests/imported-characters.html` 检查蒙皮权重、实际顶点移动、头部与姿态驱动、遮挡恢复、地面位置和四人独立实例。`tests/camera-integration.html?cast=imported` 用合成摄像头检查四人舞台，`&mode=portrait` 检查竖屏单人。

`tests/nine-actions.html` 逐项检查八位人物的九个动作，共 72 个组合，分别验证动作分类与角色表现。`tests/nine-actions-camera.html` 将合成检测结果送入正式页面，检查九个动作的识别、台词触发和舞台驱动。合成测试用于验证程序行为，真实跟拍仍受入镜范围、遮挡和光线影响。

锁骨发女生撤销第五版额外的 10% 头部缩小，脸型、五官和表情与第四版同尺寸，新发型保留。原版 Snow、Rain 和已有角色文件均保留。

人物模式显示纯卡通全身舞台，摄像头图像仅在本机用于识别。分别配对每位演员的面部、姿态与世界坐标，通过 `AvatarDriver` 驱动头、躯干、手臂、腿和脚。未入镜或低置信度的腿脚回到站姿。四个玩家可以使用同一角色，骨骼和表情相互独立。没有真实地面标定或发丝物理模拟。

`character-models.mjs` 管理八个人物和独立骨骼池，`avatar3d.js` 渲染真实全身模型，`animal-avatar3d.mjs` 保留动物头部。首次加载模型后再进入演出。

## 实际玩法

这是一个 1–4 人同屏的动作破冰游戏。玩家对着摄像头做动作，系统根据识别结果自动显示台词，并播放短音效和画面特效。台词来自预设规则，不调用大语言模型。

1. 用 Chrome、Edge 或 Safari 打开已部署的 HTTPS 网站。手机建议先横放，再开启摄像头。微信内置浏览器若不能横屏或无法稳定启动模型，请选择在系统浏览器中打开。
2. 将手机固定并适当放远，让 2–4 人横排进入画面，尽量保持相近距离。手势识别需要拍到头部、肩膀和手腕。
3. 点击“开启摄像头”预览，或直接点击“开始加戏”。首次需要下载模型，等待状态显示已启动。
4. 点击演员卡，再选八位人物或狐狸、兔子、小熊、青蛙。每位玩家独立分配角色和检测动作。
5. 选择普通、夸张或离谱档。做一个动作并短暂保持，字幕会显示演员编号和对应台词。
6. 回到自然姿势，稍等片刻，再做下一个动作。持续举手或抱头不会不断重复刷字幕。
7. 点击“结束本场 / 关闭摄像头”结束。页面切到后台也会关闭摄像头。

“台词示例”只演示预设字幕，不启动摄像头。“查看 3D 转头”打开真实网格预览，可以拖动左右转头和抬头、低头滑块，或开启自动转动。

## 9 类动作怎么做

| 动作 | 操作方法 |
|---|---|
| 扶额 | 一只手靠近额头，保持片刻。 |
| 双手抱头 | 双手放在头部两侧。手腕需要在画面中可见。 |
| 转头 | 缓慢向左或向右转头，保持脸部仍可见。 |
| 单手举高 | 单手举过头顶，另一只手放下。 |
| 双手举高 | 双手举过头顶。 |
| 挥手 | 举起一只手，左右挥动至少两个来回。静止举手会归为举手。 |
| 展开双臂 | 两臂向左右展开，手腕保持在肩膀附近的高度。 |
| 歪头 | 将头向左肩或右肩倾斜，和向左右转头是不同动作。 |
| 张嘴 | 面向镜头，明显张开嘴巴。 |

手势优先于面部动作，单帧只选择一个动作。一个动作一般需要稳定约 240 毫秒。单手和双手举高需要约 650 毫秒，手腕持续横向移动时会继续等待，避免提前消耗挥手的台词触发机会。每位玩家有独立的重复触发控制，公共字幕至少间隔 1.7 秒。多人同时做动作时会依次触发；间隔内已经结束的短动作可能不显示。

## 这次修复了什么

### 全身卡通人物

五个人物保留 21 根动作骨骼和张嘴、左右闭眼、微笑四项基础表情。脸部矩阵控制头部朝向，姿态世界坐标控制躯干与四肢。识别约 10 次每秒，显示通过骨骼插值更新，最多约 30 帧每秒；实际速度取决于设备。

头像卡片由同一实际模型生成。纯卡通舞台不显示原始摄像头画面。动物仍使用简化立体头部，保留转头、眨眼、张嘴功能。

### 更大的取景舞台

舞台改成独占整行，导演控制台移到下方。连接摄像头后隐藏大标题。当前纯卡通舞台采用独立的 16:9 画幅，摄像头横竖屏只影响识别取景，不再把竖屏视频比例套到人物舞台上。完整人物和双脚始终放在舞台范围内。

“放大舞台”使用整个浏览器窗口显示画面。“横屏多人取景”会尝试进入全屏和锁定横屏；不支持这些接口的浏览器需要手动横放手机。“切换到后置 / 前置”可切换摄像头，后置画面默认不镜像。只有一个摄像头的设备可能仍返回同一个摄像头。

程序优先申请 1280 × 720、16:9 的画面，并尽量保留传感器取景。浏览器可能按设备方向返回竖屏尺寸。网页扩大显示区域不会增加摄像头实际能拍到的范围。多人入镜仍需要横放手机、适当放远，或使用视角更合适的摄像头。

## 本地运行

本目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

浏览器打开 http://127.0.0.1:8765/ 。本版使用本地 ES 模块，请通过服务器访问。摄像头需要 localhost 或 HTTPS。

## GitHub Pages 部署与更新

本版是静态网站，不需要 npm 安装或构建。解压完整压缩包后，将下面的文件和文件夹一起上传到仓库最外层。

```text
index.html
style.css
motion.js
avatar3d.js
assets/
vendor/
README.md
```

assets 内含原来的动物 PNG。vendor 内含已固定版本的 three.module.js 和其 MIT 许可证。两者都要保留。只替换 index.html 会导致脚本或模型渲染失败。

1. 新建公开 GitHub 仓库，或打开已有项目仓库。
2. 在 Code 页面选择 Add file、Upload files，拖入解压后的全部部署文件。保留 assets 和 vendor 文件夹，提交到 main 分支。
3. 在 Settings、Pages 中选择 Deploy from a branch，分支选 main，目录选 / (root)，保存。
4. 等待部署完成，点击 Pages 中显示的 HTTPS 站点地址。
5. 更新原站点时覆盖同名文件，等待再次部署。若仍显示旧界面，可在站点网址末尾加 ?v=8，再重新打开。

## 资源、数据与限制

- Three.js 0.160.1 随项目本地提供。实际摄像头识别仍使用 MediaPipe 0.10.21。首次需要访问 jsDelivr 或 unpkg 下载运行库、WASM，并从 Google 模型存储下载识别模型。
- 识别、姿态估计和 3D 渲染在浏览器本机执行。代码不录制、不上传视频，不申请麦克风。
- FaceLandmarker 最多检测 8 张脸，PoseLandmarker 最多检测 4 个身体，游戏最多分配 4 位演员。脸与身体按位置配对，不按模型数组下标配对。
- 演员编号按位置和尺寸连续跟踪。短暂离开保留 1.2 秒。交叉走动、遮挡和离镜后返回可能交换编号或获得新编号。
- 动作使用关键点规则判断。快速动作、远距离小脸、低照度和手腕被挡可能造成漏检或误判。系统不会判断真实心理状态。
- 3D 头像后有不透明遮盖；整帧未找到头部时模糊画面。完全漏检的旁人仍可能露出，不能当作严格匿名化工具。
- 3D 渲染和两项模型推理会占用算力。实际速度受手机型号、浏览器和入镜人数影响。

## 验证

运行 `node --test tests/tracking.test.cjs tests/motion.test.cjs`，检查动作分类、挥手时序、台词配置、三维朝向数据、横竖屏比例、多人匹配和取消启动。

浏览器打开 `/tests/camera-integration.html`，可用合成四人横屏视频和单人竖屏视频检查正式页面处理流程，不调用真实摄像头。

打开 `/tests/model-smoke.html`，检查正式模型及三维矩阵、表情输出配置的初始化和空白帧推理。

本版已通过逻辑检查和合成画面集成检查。真实手机、微信内置浏览器及 2–4 人实际动作仍需现场验收，合成检查不代表真人识别准确率。
