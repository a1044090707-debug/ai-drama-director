# AI 戏精导演 V0.8 · 奶油绿立体片场

## 实际玩法

这是一个 1–4 人同屏的动作破冰游戏。玩家对着摄像头做动作，系统根据识别结果自动显示台词，并播放短音效和画面特效。台词来自预设规则，不调用大语言模型。

1. 用 Chrome、Edge 或 Safari 打开已部署的 HTTPS 网站。手机建议先横放，再开启摄像头。微信内置浏览器若不能横屏或无法稳定启动模型，请选择在系统浏览器中打开。
2. 将手机固定并适当放远，让 2–4 人横排进入画面，尽量保持相近距离。手势识别需要拍到头部、肩膀和手腕。
3. 点击“开启摄像头”预览，或直接点击“开始加戏”。首次需要下载模型，等待状态显示已启动。
4. 点击演员卡，再选狐狸、兔子、小熊或青蛙。每位玩家独立分配角色和检测动作。
5. 选择普通、夸张或离谱档。做一个动作并短暂保持，字幕会显示演员编号和对应台词。
6. 回到自然姿势，稍等片刻，再做下一个动作。持续举手或抱头不会不断重复刷字幕。
7. 点击“结束本场 / 关闭摄像头”结束。页面切到后台也会关闭摄像头。

“台词示例”只演示预设字幕，不启动摄像头。“查看 3D 转头”打开真实网格预览，可以拖动左右转头和抬头、低头滑块，或开启自动转动。

## 9 类动作怎么做

| 动作 | 操作方法 |
|---|---|
| 扶额 | 一只手靠近额头，保持片刻。 |
| 双手抱头 | 双手放在头部两侧。手腕需要在画面中可见。 |
| 转头 | 缓慢向左或向右转头，保持脸部仍可见。 |
| 单手举高 | 单手举过头顶，另一只手放下。 |
| 双手举高 | 双手举过头顶。 |
| 挥手 | 举起一只手，左右挥动至少两个来回。静止举手会归为举手。 |
| 展开双臂 | 两臂向左右展开，手腕保持在肩膀附近的高度。 |
| 歪头 | 将头向左肩或右肩倾斜，和向左右转头是不同动作。 |
| 张嘴 | 面向镜头，明显张开嘴巴。 |

手势优先于面部动作，单帧只选择一个动作。一个动作一般需要稳定约 240 毫秒。单手和双手举高需要约 650 毫秒，以免把挥手开始时的举手误当成静态举手。每位玩家有独立的重复触发控制，公共字幕至少间隔 1.7 秒。多人同时做动作时会依次触发；间隔内已经结束的短动作可能不显示。

## 这次修复了什么

### 真正的 3D 头部

实时遮脸改为 Three.js 绘制的立体网格。狐狸、兔子、小熊和青蛙均有封闭的头部、耳朵、眼睛和突出的鼻口结构，转头时能看到侧面。它们是简化的卡通模型，原有毛绒插图继续用于待机示意和角色卡。

MediaPipe 输出的 facialTransformationMatrixes 决定头部三维朝向，包括左右转头、抬头低头和歪头。矩阵缺失时使用三维面部关键点估计朝向。每位演员分别平滑旋转。张嘴和眨眼系数用于模型的简单表情变化。

浏览器不支持 WebGL 或图形上下文丢失时，保留 2D 备用遮脸，并在画面中标明“2D 备用遮脸”。备用图片不能显示真正的立体侧面。

### 更大的取景舞台

舞台改成独占整行，导演控制台移到下方。连接摄像头后隐藏大标题，按摄像头实际返回的宽高设置舞台比例。竖屏画面会占满可用宽度，不再被固定横向容器夹成中间的一条窄画面。

“放大舞台”使用整个浏览器窗口显示画面。“横屏多人取景”会尝试进入全屏和锁定横屏；不支持这些接口的浏览器需要手动横放手机。“切换到后置 / 前置”可切换摄像头，后置画面默认不镜像。只有一个摄像头的设备可能仍返回同一个摄像头。

程序优先申请 1280 × 720、16:9 的画面，并尽量保留传感器取景。浏览器可能按设备方向返回竖屏尺寸。网页扩大显示区域不会增加摄像头实际能拍到的范围。多人入镜仍需要横放手机、适当放远，或使用视角更合适的摄像头。

## 本地运行

本目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1
```

浏览器打开 http://127.0.0.1:8765/ 。本版使用本地 ES 模块，请通过服务器访问。摄像头需要 localhost 或 HTTPS。

## GitHub Pages 部署与更新

本版是静态网站，不需要 npm 安装或构建。解压完整压缩包后，将下面的文件和文件夹一起上传到仓库最外层。

```text
index.html
style.css
motion.js
avatar3d.js
assets/
vendor/
README.md
```

assets 内含原来的动物 PNG。vendor 内含已固定版本的 three.module.js 和其 MIT 许可证。两者都要保留。只替换 index.html 会导致脚本或模型渲染失败。

1. 新建公开 GitHub 仓库，或打开已有项目仓库。
2. 在 Code 页面选择 Add file、Upload files，拖入解压后的全部部署文件。保留 assets 和 vendor 文件夹，提交到 main 分支。
3. 在 Settings、Pages 中选择 Deploy from a branch，分支选 main，目录选 / (root)，保存。
4. 等待部署完成，点击 Pages 中显示的 HTTPS 站点地址。
5. 更新原站点时覆盖同名文件，等待再次部署。若仍显示旧界面，可在站点网址末尾加 ?v=8，再重新打开。

## 资源、数据与限制

- Three.js 0.160.1 随项目本地提供。实际摄像头识别仍使用 MediaPipe 0.10.21。首次需要访问 jsDelivr 或 unpkg 下载运行库、WASM，并从 Google 模型存储下载识别模型。
- 识别、姿态估计和 3D 渲染在浏览器本机执行。代码不录制、不上传视频，不申请麦克风。
- FaceLandmarker 最多检测 8 张脸，PoseLandmarker 最多检测 4 个身体，游戏最多分配 4 位演员。脸与身体按位置配对，不按模型数组下标配对。
- 演员编号按位置和尺寸连续跟踪。短暂离开保留 1.2 秒。交叉走动、遮挡和离镜后返回可能交换编号或获得新编号。
- 动作使用关键点规则判断。快速动作、远距离小脸、低照度和手腕被挡可能造成漏检或误判。系统不会判断真实心理状态。
- 3D 头像后有不透明遮盖；整帧未找到头部时模糊画面。完全漏检的旁人仍可能露出，不能当作严格匿名化工具。
- 3D 渲染和两项模型推理会占用算力。实际速度受手机型号、浏览器和入镜人数影响。

## 验证

运行 `node --test tests/tracking.test.cjs tests/motion.test.cjs`，检查动作分类、挥手时序、台词配置、三维朝向数据、横竖屏比例、多人匹配和取消启动。

浏览器打开 `/tests/camera-integration.html`，可用合成四人横屏视频和单人竖屏视频检查正式页面处理流程，不调用真实摄像头。

打开 `/tests/model-smoke.html`，检查正式模型及三维矩阵、表情输出配置的初始化和空白帧推理。

本版已通过逻辑检查和合成画面集成检查。真实手机、微信内置浏览器及 2–4 人实际动作仍需现场验收，合成检查不代表真人识别准确率。
